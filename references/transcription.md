# 转写与 Obsidian 渲染规范

## 总原则：忠实 > 漂亮

- **不增**：图片里没有的定义、例子、结论、数值、推导步骤，一律不写。不要用你自己的知识「补全」老师的板书。
- **不改**：认为原内容有错时，照原文转写，另起 `> [!question] 待核对` 说明你的怀疑，不要静默修正。
- **不译**：保持原语言。英文教材就写英文，除非用户明确要求翻译。
- **不摘要**：定义、推导、例题、公式、老师在旁边写的批注（「重点」「必考」「作业」）都要保留。批注可用 `> 老师批注：…` 或加粗呈现。
- 允许做的只是**结构化**：加标题层级、把散乱文字整理成列表/表格、统一代码缩进、补 Markdown 语法。

## 不确定内容的标记

看不清、认不准、被手挡住的地方，用下面三种之一，**不要猜一个看起来合理的字填进去**：

| 场景 | 写法 |
| :-- | :-- |
| 句中某几个字模糊 | `==[?不确定: 此处字迹模糊，疑似「收敛」]==` |
| 整段/整题无法辨认 | `> [!warning] 待核对`<br>`> 第 3 题的推导过程图片中被裁掉，需补拍` |
| 公式某处存疑 | `$x^{==[?不确定: 2 还是 3]==}$` 或把整条公式放进 `> [!warning] 待核对` |

同时把每一条不确定项通过 `--uncertain "..."` 传给脚本（可重复多次）。脚本会：

- 在 frontmatter 写 `has_uncertain: true`；
- 若该项没有出现在正文里，自动追加一个 `> [!warning] 待核对` callout；
- 在报告里提示用户「有未能识别的部分」。

正文里只要出现上述任一标记，脚本也会自动把 `has_uncertain` 置为 true。

## 公式（LaTeX）

- 行内：`$...$`；独立公式：`$$...$$`，并让 `$$` **独占一行**（与前后文字同行时 Obsidian 常常不渲染）。
- 多行推导用环境，不要用 `\\` 硬换行到环境外：

```latex
$$
\begin{aligned}
\lim_{x \to 0} \frac{\sin x}{x} &= 1 \\
\lim_{x \to \infty} \left(1 + \frac{1}{x}\right)^x &= e
\end{aligned}
$$
```

- 常用环境：`aligned`、`cases`、`matrix`/`pmatrix`/`bmatrix`、`gathered`。Obsidian 用 MathJax，`\begin{equation}`、`\label`、`\ref`、`\eqref` 不可靠，**不要用**。
- 不要用的命令：`\usepackage`、`\documentclass`、`\begin{document}`、`\input`、`\includegraphics`、`\cite`、`\bibliography`、`\mathds`、`\newpage`、`\caption`。需要黑体数集就写 `\mathbb{R}`（MathJax 内置）。
- `%` 在公式里是注释符，要写百分号必须转义成 `\%`。
- 正文里表示美元/价格的 `$` 要写成 `\$`，否则会被当成公式定界符。
- 中文字符放进公式时用 `\text{...}` 包裹：`$P(\text{事件}A)$`。
- `\left(` 与 `\right)` 必须成对；`{` `}` 必须配对；`\begin{x}` 必须有 `\end{x}`。

脚本会用 `validate` 把这些确定性问题查出来（括号配对、环境闭合、`$$` 奇偶、脆弱宏、未转义 `%`、代码围栏未闭合、标题缺空格、表格列数不一致），并把告警写进报告。**默认只告警不阻断**，但你应当在汇报里转达，并优先在生成正文时就修正。

## Obsidian 渲染注意点

- 标题 `#` 后必须有空格：`## 极限`，写成 `##极限` 会被当成标签。
- 表格需要分隔行，且每行列数一致：

```markdown
| 类型 | 字节 | 取值范围 |
| :-- | --: | :-- |
| `int` | 4 | -2^31 ~ 2^31-1 |
```

- 代码块用三反引号并标语言（```c、```python、```text），务必闭合。表格单元格里如需换行用 `<br>`。
- 高亮 `==文字==`、加粗 `**文字**`、任务列表 `- [ ]` 都可用。
- 图片嵌入用 `![[文件名]]`。脚本会自动把你写的嵌入链接改写成附件在 vault 中的**最终文件名**（附件重名时会被加后缀），所以你按原图文件名写即可。若正文里完全没有嵌入，脚本会自动追加一个 `## 原图` 小节。
- 文件名里不能出现 `# ^ [ ] | < > : " / \ ? *`，脚本会清洗成 `_`；因此笔记内引用附件时不要手写这些字符。
- 双向链接 `[[笔记名]]` 可以指向 vault 里已有笔记（例如把 `[[重要极限]]` 关联起来），但**不要编造不存在的链接目标**，除非用户要求。

## 图示 / 图表 / 示意图

无法用文字完整表达的图（几何图、电路图、内存布局图、流程图、函数图像）：

1. 先用文字客观描述图里有什么（坐标轴、标注、箭头方向、各部分名称与数值），只描述你确实看到的；
2. 保留原图嵌入（脚本会自动处理），让读者对照；
3. 只有当结构完全确定时，才可以用 Mermaid 代码块重绘流程图/关系图，并注明「根据原图重绘」；不确定就只用文字描述 + 原图。

```markdown
### 内存布局示意

原图为一个从低地址到高地址的纵向条状图，自上而下依次标注：栈区（向下增长 ↑）、
堆区（向上增长 ↓）、全局/静态区、常量区、代码区。箭头方向表示增长方向。

![[C-数据类型-内存占用.png]]
```

## 笔记结构模板

按图片实际内容取用，不要硬凑小节：

````markdown
## 核心概念

（定义、定理、公式，忠实转写）

## 例题

**题目**：…

**解**：…

## 代码

```c
/* 原样转写，保留老师的注释 */
```

## 老师批注 / 重点

> 必考：…

> [!warning] 待核对
> - 第 2 行公式的下标看不清
````

frontmatter 由脚本生成，字段为 `title` / `course` / `date` / `source`（原图文件名）/ `source_sha256`（重复检测用）/ `tags` / `has_uncertain` / `classified_by` / `tool`。你在正文里自带的 frontmatter 会被合并：同名字段以脚本生成的为准，其它字段原样保留。

## 多张图片

- 明显是同一篇笔记的连续页 → 合并成一篇，按页序组织，所有原图都作为附件传入 `--image`（可重复），`source` 字段会列出全部原图。
- 不同主题 / 不同课程 → 用 job JSON 分成多篇，脚本会一次性处理，任何一篇失败默认整批回滚（不留半成品）。
- 同一张图重复发送 → 脚本按内容哈希识别，默认不重复生成，并告诉你它上次被整理进了哪篇笔记。
